When you apply this stack, Terraform does three things in order.

1. Request the certificate
   aws_acm_certificate asks ACM for a cert covering simsoliver.com and
   *.simsoliver.com. ACM does not issue it yet. It replies with “prove you
   own this domain by creating this CNAME.”

2. Create the CNAME
   aws_route53_record writes that CNAME into the public hosted zone.
   In Route 53 you will see an underscore record, for example:
   _<hash>.simsoliver.com  CNAME  _<hash>.acm-validations.aws
   That record is created during apply so ACM can check it. It does not
   appear after the cert is already issued. Leave it in place; ACM uses
   it again for renewal.

3. Wait for ACM
   aws_acm_certificate_validation sits there until ACM looks up that
   CNAME on the public internet and marks the cert Issued. Then the
   apply finishes.

The CNAME in the hosted zone means the validation record was created.
The certificate itself is in ACM (Certificate Manager). Status Issued
is the confirmation that ACM accepted the CNAME.

If this stack appears stuck, ACM cannot see the CNAME on the public
internet. The usual cause is that the domain’s registrar nameservers
do not match this hosted zone’s NS records. Fix the nameservers, then
re-apply. Terraform will wait (up to about 75 minutes) until the cert
is Issued.
