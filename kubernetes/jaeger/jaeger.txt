Jaeger
======

What it does
------------
Jaeger is the cabinet for traces. A trace is one customer's trip
through the shop. Each step is a span (who, what, when, how long,
success or error). All steps share a trace id. Jaeger shows that
as a timeline, not a paragraph of English.

Shop pods do not send traces to Jaeger themselves. They send OTLP
(OpenTelemetry Protocol) to otelcol (OpenTelemetry Collector).
otelcol forwards traces here on port 4317.

UI (two doors, same website):
  https://jaeger.simsoliver.com/jaeger/ui
  https://shop.simsoliver.com/jaeger   (frontendproxy)

Traces are stored in memory on this pod. Restart Jaeger and the
timeline is empty. Demo only — no disk.


Related services
----------------
frontendproxy looks up opentelemetry-demo-jaeger-query on 16686.
Envoy routes /jaeger to that Service.

ingress.yaml exposes the same UI on jaeger.simsoliver.com
(ALB + ExternalDNS). Health check path: /jaeger/ui.

otelcol sends OTLP to this Service on port 4317.

Lives in namespace otel-demo (same as the rest of the shop).


Files
-----
  cm.yaml      Jaeger config (memory storage, UI, OTLP :4317)
  deploy.yaml  one Jaeger pod (probes use /status on 13133)
  svc.yaml     ClusterIP named opentelemetry-demo-jaeger-query
               (16686 UI, 4317 OTLP gRPC)
  ingress.yaml public ALB → UI :16686 (jaeger.simsoliver.com)
