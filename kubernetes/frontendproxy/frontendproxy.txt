Frontend proxy
==============

What it does
------------
Envoy reverse proxy — the in-cluster front door. The AWS load
balancer (Ingress) sends public traffic here. Envoy then routes
to the right in-cluster Service:

  /                 frontend (the website)
  product images    imageprovider
  flagd UI          flagd :4000
  locust            loadgenerator
  /otlp-http        otelcol (OpenTelemetry Collector) :4318  (browser traces)
  /jaeger           jaeger :16686  (UI — traces after otelcol forwards them)

Grafana hostname is still in the Envoy env; that Service is not
in kubernetes/ (Grafana lives in monitoring). Jaeger is in
kubernetes/jaeger/ as opentelemetry-demo-jaeger-query.


Related services
----------------
Routes to:
  frontend, imageprovider, flagd, loadgenerator, otelcol (OpenTelemetry Collector),
  jaeger

Called by:
  Ingress (public ALB, host shop.simsoliver.com)
  loadgenerator (fake shoppers hit the proxy, not frontend)

Envoy also has FLAGD_HOST / FLAGD_UI_* so it can proxy the flagd
API and UI. That is routing, not the shop's OpenFeature clients.

Also sends telemetry to otelcol (OpenTelemetry Collector).
